## 3. 기술 스택 후보 비교

요구사항: 모바일 웹 · 카카오/구글 로그인 · PG 결제 · 공유 링크별 OG 이미지 · 부적 이미지 생성 · 5주 · 백엔드 2명.

| | **A. Next.js + Spring Boot** | **B. Next.js 풀스택 + Supabase** | **C. React SPA(Vite) + Spring Boot** |
|---|---|---|---|
| 구성 | Next.js(App Router, TS)는 화면·OG·이미지 라우트, Spring Boot는 API·결제·사주 | Next.js 서버 라우트가 API, Supabase가 Auth(카카오/구글)·Postgres·Storage | 정적 SPA + Spring API |
| 장점 | 백엔드 2명이 Spring에 익숙하면 가장 빨리 병렬 작업 가능. 결제·도메인 로직을 BE가 온전히 소유. 링크별 OG/SSR 가능 | 저장소·언어 하나, 인프라 최소, 소셜 로그인 설정이 가장 빠름. BE가 FE 화면을 도와주기 쉬움 | FE 구조가 가장 단순 |
| 단점 | 배포 대상 2개, 인증 쿠키/CORS 설정 필요 (Next.js rewrites로 `/api`를 프록시하면 해결) | 백엔드 2명이 TS에 익숙해야 함. 로직이 라우트 곳곳에 흩어지기 쉬움 | **링크별 OG 미리보기가 안 됨** → 선물 링크가 카톡에서 밋밋하게 보임. 봇용 HTML을 BE가 따로 렌더해야 함 |
| 5주 적합도 | 높음 (BE가 Spring 숙련이면) | 높음 (BE가 TS 가능하면) | 낮음 |

**추천: A안 (Next.js + Spring Boot)** — 단, D-14(백엔드 주 언어)에서 "백엔드 2명 모두 TS가 편하다"로 확정되면 B안으로 바꾼다. 어느 쪽이든 **프론트는 아래 3-1로 확정**이다.

### 3-1. 프론트엔드 스택 — ✅ 확정 (2026-09-26)

Next.js(App Router)+TypeScript · Vercel · pnpm · Tailwind + CSS 변수 토큰 · 손그림 SVG `border-image` · 글꼴 보류(FONT-HOLD) · vaul/Radix · TanStack Query · openapi-typescript+openapi-fetch · RHF+Zod · Zustand(선물 위저드 한정) · dayjs(Asia/Seoul) · `next/og`+Kakao SDK · Biome/Vitest/Playwright · Sentry/PostHog.

선택 이유와 렌더링·뷰포트 원칙은 **[`frontend/docs/FRONTEND.md`](../frontend/docs/FRONTEND.md) 1장**에 있다.

### 3-2. 백엔드 · 인프라 — 미확정 (D-14)

A안 기준 제안:
- BE: Spring Boot 3, Spring Security OAuth2 Client(카카오/구글), JPA, PostgreSQL. 컨테이너 배포(Cloud Run / Railway 등 팀이 써본 곳).
- 도메인: `/api/*`를 Next.js rewrites로 Spring에 프록시 → 같은 출처라 쿠키·CORS 문제 없음. 카카오톡 인앱브라우저에서도 안전.
- 결제: **포트원(PortOne) V2 + PG 1곳**을 1순위로 검토. 한 PG가 반려해도 코드 수정 없이 다른 PG로 갈아탈 수 있다는 점이 이번 일정에서 가장 큰 가치. 대안은 토스페이먼츠 직접 연동(문서·테스트 키 접근성이 좋음). 수수료·조건은 P0 상담에서 확인.
- 사주 계산: 만세력 라이브러리 후보 2개를 P3 스파이크에서 선택하도록 비교 (예: 6tail `lunar` 계열은 Java/JS 버전이 모두 있음). 결과는 기존 만세력 사이트와 대조해 테스트로 고정.
- 부적 이미지: 서버에서 PNG 생성(방식은 백엔드 스택 확정 후). OG 이미지는 FE 저장소의 `next/og` 라우트, 입력 데이터는 API가 제공. 담당 BE-B.
- 스토리지: S3 호환 오브젝트 스토리지(부적 PNG 보관).
- 관측(백엔드): 서버 에러 추적, 결제 실패 알림은 팀 메신저 웹훅.

## 9. 출시 범위 컷 라인

- **Must (없으면 출시 안 함)**: 로그인·내 정보, 결제 파이프라인, 수능운 본인 결제 흐름, 선물하기(구매자+수신자), 부적 저장·공유, 약관 3종·사업자 정보
- **Should**: 마이페이지(저장된 사람들), 오늘의 운세(무료), 링크별 OG 이미지
- **Could**: 부적 창고 도감, 유료 운세(애정운), 만화 인트로, 재화
