## 1. 제품 개요

뿌기사주는 전통 명리학을 귀여운 손그림 감성으로 풀어낸 모바일 웹서비스다. 사용자는 무료 오늘의 운세를 확인하고, 충전형 재화인 **등껍질**로 일반·이벤트 운세와 부적을 구매할 수 있다. 다른 사람에게는 등껍질로 수능운·부적을 한 번 선물할 수 있다. 원화 결제는 등껍질 충전에만 쓴다.

핵심 사용자는 수능을 앞둔 수험생과 그들을 응원하는 가족·친구지만, 1차 출시부터 종합운·애정운·재물운·궁합·신살을 함께 제공해 수능 이후에도 사용할 수 있는 상품 구조를 만든다.

### 대회 맥락

- 2026 신촌 연합 SW 창업 경진 대회 출품작이다.
- 2026-10-31 Kick-Off를 공개 출시 시점으로 삼는다.
- 2026-11-19 수능까지 약 19일 동안 수능운과 선물 상품의 판매가 집중될 것으로 본다.
- 2026-11-21 데모데이에서 실제 결제 성과와 제품을 발표한다.
- 평가에 사용할 수 있도록 PG 결제 완료 금액, 취소·환불, 실제 정산액을 처음부터 구분해 기록한다.
- 창업인증서 기준·NFC 매출 인정 비율·부스 가점 등은 대회 규정 원문 확인 전까지 확정 사실로 사용하지 않는다.

### 세계관

뿌기는 사주나라에서 명단을 보고 사람들에게 행운을 배달하던 거북이다. 거센 바람에 명단과 행운을 잃어버려 지상으로 떨어진 뒤, 직접 사람들의 사주를 살펴 행운의 주인을 찾아준다. 걸음이 느린 뿌기를 12지 동물 친구들이 돕는다.

- 오늘의 운세: 뿌기가 오늘 발견한 행운 소식
- 유료·이벤트 운세: 뿌기가 사용자에게 맞는 행운을 찾는 과정
- 부적: 찾은 행운을 사용자가 간직할 수 있는 형태로 전달
- 선물: 수신자의 띠 동물이 행운을 대신 배달
- 사용자의 구매·수신·수집 경험은 장기적으로 뿌기의 귀환 미션과 연결할 수 있으나 진행도 UI는 MVP에서 제외한다.

## 2. 문제와 기회

### 사용자 문제

- 기존 사주 서비스는 결과가 무겁거나 복잡해 10~20대가 짧게 소비하기 어렵다.
- 시험·면접처럼 특정 날짜를 앞둔 사용자는 일반적인 장기 운세보다 당일 행동에 연결되는 콘텐츠를 원한다.
- 응원하는 사람이 디지털 운세·부적을 간단히 선물하고 싶어도 수신자의 민감한 생년정보를 대신 입력하기 어렵다.
- 디지털 결과를 결제한 뒤 다시 찾거나 저장·공유하기 어려운 서비스가 많다.

### 제품 기회

- 결과를 한줄 요약, 행동 팁, 준비물, 행운 요소처럼 바로 소비할 수 있는 단위로 제공한다.
- 수신자가 직접 정보를 입력하는 토큰 링크로 선물 구매자와 수신자의 역할을 분리한다.
- 12지 캐릭터와 배경화면형 부적으로 수집·공유 동기를 만든다.
- 결정적인 만세력 계산과 최초 AI 생성 결과의 스냅샷 재사용으로 신뢰성과 재현성을 확보한다.

### 핵심 차별점

- 수능일에 맞춘 이벤트 운세와 D-day 선물
- 수능 1~5교시별 흐름과 집중 포인트
- 사주에 기반한 도시락·간식 추천, 이유와 대안 메뉴
- 공통 준비물과 개인 행운 아이템을 합친 체크리스트
- 결과와 결합한 12지 캐릭터 부적의 저장·공유 경험
- 선물 수신자가 로그인 없이 결과를 보고 다시 본인용 상품으로 유입되는 바이럴 루프

## 3. 목표

### 출시 목표

1. 사용자가 카카오 로그인 후 등껍질을 충전하고 6종 운세 중 하나를 구매·열람할 수 있다.
2. 구매자가 모든 운세 유형을 단건 상품으로 선물할 수 있다.
3. 수신자는 알림톡으로 받은 링크에서 로그인 없이 자신의 정보를 입력하고 결과를 볼 수 있다.
4. 구매 결과와 부적을 다시 열람·저장·공유할 수 있다.
5. 결제·재화 차감·환불이 중복 없이 추적 가능하고 장애 시 복구된다.
6. 2026-10-31부터 11-21까지의 결제 완료 금액과 정산액을 구분해 집계한다.

### 비목표

- 생성형 AI 기반 상담 채팅과 자유 질문·메모 해석
- 의료 진단·치료 또는 합격·재물 증가를 보장하는 표현
- 1차 출시의 구글 로그인과 휴대폰 소액결제
- 해외 출생 시간대 및 출생지 진태양시 보정
- 만화형 브랜드 인트로
- 12지 도감 완성 보상
- NFC 키링 판매·제작

## 5. 상품 체계

### 운세 유형

| 분류 | 유형 | 추가 입력 |
|---|---|---|
| 일반 | 애정운 | 선택형 관심 항목 |
| 일반 | 종합운 | 선택형 관심 항목 |
| 일반 | 재물운 | 선택형 관심 항목 |
| 일반 | 궁합 | 상대방 정보·관계 |
| 일반 | 신살 | 선택형 관심 항목 (유지 여부 `TBD(F-03)`) |
| 이벤트 | 수능운 | 없음 (대학수학능력시험, 시험일은 서버 설정값) |

### 본인용 가격

| 상품 | 가격 | 비고 |
|---|---:|---|
| 일반 운세 `사주` | 등껍질 10개 | |
| 일반 운세 `사주+부적` | 등껍질 15개 | 첫 구매 때 함께 사는 번들 할인 |
| 일반 운세 부적 추가 구매 | 등껍질 10개 | 결과 마지막 `부적 받기` |
| 수능운 (부적 포함) | 등껍질 15개 | 정가 20개에서 할인한 가격으로 표기 |

- 화면 수량 표기는 `등껍질 N개`다.
- 수능운에는 `사주` 단독 옵션과 부적 추가 구매가 없다.
- 가격·정가는 서버 상품 카탈로그 값을 표시한다 (P-03).

### 충전 상품

| 유료 | 보너스 | 총 지급 | 가격 |
|---:|---:|---:|---:|
| 10 | 0 | 10 | 1,000원 |
| 30 | 3 | 33 | 3,000원 |
| 50 | 6 | 56 | 5,000원 |
| 100 | 14 | 114 | 10,000원 |
| 300 | 46 | 346 | 30,000원 |
| 500 | 82 | 582 | 50,000원 |

- 1,000원 상품은 보너스가 없다.
- 유료 등껍질과 보너스 등껍질은 원장에서 구분한다.

### 선물 상품

- 선물은 단건 상품만 제공한다.
- 1차 출시는 수능운만 선물할 수 있다.
- 선물도 등껍질로 결제한다 (P-07).
- 선물 옵션은 `부적` / `부적+사주`다. 선물에는 `사주` 단독 옵션을 제공하지 않는다.

| 선물 (수능운) | 가격 |
|---|---:|
| `부적` | 등껍질 10개 |
| `부적+사주` | 등껍질 15개 |

- `부적` 선물은 부적·편지·수능 체크리스트를 제공한다.
- `부적+사주` 선물은 부적·편지·수능운 결과·수능 체크리스트를 제공한다.

## 6. 핵심 사용자 흐름

### 무료 오늘의 운세

1. 비로그인 방문자가 생년정보를 입력한다.
2. 같은 인물·같은 날짜에 동일한 오늘의 운세를 확인한다.
3. 한줄 운세, 행운 색·아이템·장소, 오늘의 행동을 본다.
4. 결과를 공유하거나 관련 유료 상품으로 이동한다.

### 본인용 운세 구매

1. 운세를 선택한다.
2. 카카오 로그인 후 본인 또는 저장된 사람을 선택한다.
3. 필요한 추가 항목을 선택한다.
4. 일반 운세는 `사주` 또는 `사주+부적`을 선택한다. 수능운은 부적 포함 단일 상품이다.
5. 잔액 부족 시 충전하고 기존 진행 상태로 복귀한다.
6. 서버가 등껍질을 차감하고 결과 스냅샷을 생성한다.
7. 결과를 열람하고, 일반 운세 `사주` 구매자는 필요하면 부적을 추가 구매한다. 부적은 결과의 부족한 기운으로 자동 생성된다.

### 선물 구매

1. 로그인 사용자가 선물 옵션(`부적` / `부적+사주`)을 선택한다. 1차 선물은 수능운만이다.
2. 수신자 이름 또는 닉네임, 휴대전화번호, 200자 이하 편지를 입력한다.
3. 등껍질로 결제한다. 잔액이 부족하면 충전 후 돌아온다.
4. 결제가 완료되면 추측 불가능한 선물 링크가 생성된다.
5. 서비스가 링크를 포함한 카카오 알림톡을 수신자에게 발송한다.

### 선물 수신

1. 수신자가 알림톡의 링크를 로그인 없이 연다.
2. 본인의 생년월일시·성별을 직접 입력한다.
3. 최초 제출 후 정보가 잠긴다.
4. 공개된 운세·부적·보낸 사람 메시지를 확인한다.
5. 로그인하면 부적 창고 저장과 계정 기반 복원이 가능하다.
6. `다른 운세도 보러가기` CTA로 본인용 무료·유료 운세에 진입한다.

## 7. 기능 요구사항

### 인증·계정

- 1차 출시는 카카오 OAuth만 제공한다.
- 로그인 직후 본인 정보 입력을 강제하지 않는다.
- 계정당 최대 5개 활성 세션을 허용한다.
- 탈퇴 즉시 접근을 차단하고 개인정보·결과를 최대 30일 내 삭제한다.

### 인물 정보

- 양력·음력·윤달, 1900-01-01~현재 날짜를 지원한다.
- 태어난 시·분 또는 시간 모름을 제공한다.
- 다른 사람은 본인 제외 최대 10명까지 저장한다.
- 타인 정보 입력 권한 확인을 받는다.

### 등껍질

- 충전·사용·환급·조정·소멸을 불변 원장으로 기록한다.
- 충전 시 유료분과 보너스분을 별도 원장 항목으로 지급한다.
- 클라이언트가 금액·차감량을 결정하지 않는다.
- 충전 결제 승인 즉시 지급한다. 유료 등껍질은 지급일로부터 5년, 보너스 등껍질은 1년 유효하다.
- 유효기간이 먼저 끝나는 것부터, 같으면 보너스부터 차감한다 (P-02A).
- 시스템 실패 시 보상 거래로 자동 환급한다.

### 운세·콘텐츠

- 사주 원국, 간지, 십성, 12운성, 합충형파해, 대운·세운 등 결정론적 명리 계산은 오픈소스 만세력 라이브러리와 서버 계산 엔진이 담당한다.
- Liner API 기반 생성형 AI는 계산 엔진이 반환한 구조화된 JSON만 입력받아 사용자용 사주 해석과 설명 문장을 생성한다. 생성형 AI를 결정론적 명리 계산에는 사용하지 않는다.
- Liner API에는 필요한 계산 결과와 상품·이벤트 맥락만 전달하며, 원본 생년월일시 등 불필요한 개인정보는 전달하지 않는다.
- AI는 입력 JSON에 없는 명리 정보를 임의로 계산·보완·추론해서는 안 된다. 필요한 계산값이 없으면 해당 내용을 생성하지 않고 관련 항목을 제외하거나 계산 제한을 안내한다.
- AI 상담 채팅과 자유 입력 기반 추가 해석은 제공하지 않는다. 선택형 관심 항목만 생성 맥락으로 사용한다.
- 자유 메모를 결과 생성에 사용하지 않는다.
- 구매 결과는 `calculationVersion`, `generationVersion`, `contentVersion`과 함께 스냅샷 저장한다.
- 같은 정규화 입력·상품·기준일·계산/생성 버전은 최초 생성 결과를 재사용해 같은 결과를 반환한다.
- 수능 결과는 교시별 조언, 추천 음식의 이유·대안, 공통 준비물과 개인 행운 아이템을 구조화해 제공한다.

### 부적

- 띠 기반 12지 캐릭터를 사용한다.
- 부적은 고르지 않는다. 운세 결과의 부족한 기운(오행 색)·사용자 띠·문구 풀로 서버가 자동 생성한다 (T-01).
- 원본은 1080×1920 PNG, 썸네일은 360×640 WebP다.
- 개인정보를 이미지에 포함하지 않는다.
- 저장·공유 이미지에 작은 `뿌기사주` 브랜드를 표시한다.

### 선물

- 수신자 휴대전화번호는 알림톡 발송에만 사용하고 화면·로그·분석 데이터에서 마스킹한다.
- 결제 승인 후 알림톡 발송 요청과 결과를 추적한다.
- 일반 운세 결과와 부적 공유는 카카오톡 공유하기를 제공하되 선물 주문·전달과 구분한다.

- 구매자가 수신자의 생년정보를 입력하지 않는다.
- 링크 토큰은 32바이트 이상의 안전한 난수이며 gift에는 해시만 저장한다. 알림톡 발송용 원문 URL은 암호화된 outbox에서 한시적으로만 보관한다.
- 메시지는 200자, 이모지·줄바꿈을 허용하고 금칙어를 검사한다.
- 새 링크를 발급하면 이전 링크를 즉시 폐기한다.

### 관리자

- 역할을 `ADMIN`과 `CS`로 분리한다.
- 개인정보는 기본 마스킹한다.
- 개인정보 조회·환불·잔액 조정·토큰 재발급을 감사 로그에 남긴다.
- 운영자가 생년월일을 직접 수정할 수 없다.

## 9. 정책·보안 원칙

- 결제·구매·결과 생성·환불은 멱등하게 처리한다.
- 세션 쿠키는 운영에서 `HttpOnly + Secure + SameSite=Lax`를 사용한다.
- 상태 변경 요청은 CSRF와 Origin 검증을 적용한다.
- PG 시크릿·OAuth 시크릿·토큰 원문을 로그나 클라이언트에 노출하지 않는다.
- PostHog에는 이름·생년월일시·성별·메시지를 전송하지 않는다.
- 결과와 결제 화면에 재미·참고용 콘텐츠 고지를 표시한다.

## 12. 출시 승인 기준

- 본인 운세, 충전, 선물 구매, 선물 수신 흐름을 실제 모바일 환경에서 완주한다.

- 테스트 카드 결제·부분/전체 취소와 재화 자동 환급을 확인한다.

- 결과 스냅샷이 콘텐츠 배포 후에도 바뀌지 않는다.
- 약관·개인정보처리방침·환불정책·사업자 정보가 노출된다.
- Critical/Blocker 결함이 0건이다.
