# 사주 계산 정책 — `manse-2026.10-v1`

상태: 구현 기준 초안. 명리 검수자가 승인하기 전에는 새 계산 규칙을 이 문서만으로 채택하지 않는다.

## 적용 범위

- 기준 시간대는 `Asia/Seoul` (KST)이다.
- 입력은 양력 또는 한국 음력이며, 음력 윤달은 입력값으로 명시한다.
- 양력/음력 변환은 `korean-lunar-0.4.0`, 절기·간지·대운 계산은 `lunar-java-1.7.7`을 사용한다.
- `1900-01-01`부터 요청 시점의 KST 날짜까지의 출생일만 정상화한다. 엔진 회귀 fixture의 미래 날짜는 라이브 입력 정책이 아닌 라이브러리 회귀 확인용 합성 사례다.

## 현재 결정된 계산 규칙

| 항목 | 현재 정책 | 코드 근거 |
| --- | --- | --- |
| 연주·월주 | KST 시각을 절입 시각과 비교한다. 라이브러리 절기 시각(UTC+8)을 실제 KST instant와 맞추기 위해 절기 조회 시 벽시계를 1시간 보정한다. | `DeterministicSajuEngine` |
| 일주 전환 | 자정(00:00) 기준이다. 야자시 별도 전환은 적용하지 않는다. | `CalculationPolicy.DayBoundary.MIDNIGHT` |
| 시주 | 출생 시각이 있을 때만 계산한다. | `DeterministicSajuEngine` |
| 출생 시각 미상 | 시주·시주 십성·12운성·대운/세운을 반환하지 않는다. 그 날짜에 연주 또는 월주 절입 경계가 있으면 추정하지 않고 거절한다. | `DeterministicSajuEngine` |
| 진태양시·역사 DST | 적용하지 않는다. | `CalculationPolicy` |

## 변경 관리와 검수

계산 규칙·라이브러리·경계 처리 중 하나라도 바뀌면 `calculationVersion`을 올리고 골든 fixture, 변경 근거, 영향 요약을 함께 검토한다. 기존 구매 결과는 당시 snapshot을 재계산으로 교체하지 않는다.

골든 fixture에는 실제 사용자 이름, 계정 ID, 연락처 또는 실제 생년정보를 넣지 않는다. 현재 회귀 사례는 합성 입력이며, 외부 만세력과 명리 검수자가 독립적으로 확인한 사례로 대체·확장해야 한다.

## 미결 사항

- 역사적 timezone 데이터 적용 범위
- 절기 경계일에서 출생 시각 미상 입력을 제한 결과로 허용할지 여부
- 음력 데이터 공급원 변경·업데이트 절차
