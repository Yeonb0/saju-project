## 1. 공통 규칙

### 지원 환경

- 모바일 웹 우선, 앱 기둥 최대 폭 402px
- iOS Safari, Android Chrome, 카카오톡 인앱브라우저
- `100dvh`, safe-area 반영
- 날짜·D-day·콘텐츠 공개는 `Asia/Seoul`

### 공통 UI

- `AppShell`: 헤더, 뒤로가기, 메뉴, 본문, 하단 고정 CTA
- 뒤로가기는 브라우저 기록이 아닌 명시적 라우트 링크를 기본으로 한다.
- 🆕 사이드 메뉴(`HOME-04`): 홈, 마이페이지, 내 부적 창고, 오늘의 운세, 유료 운세, 수능운
- 비동기 화면은 로딩·빈 상태·실패·재시도 상태를 모두 제공한다.
- 결제·재화·선물 CTA는 처리 중 중복 입력을 막는다.
- 모든 금액·재화 차감량은 서버 응답을 표시한다.
- 🆕 재화 표기 단위는 `등껍질 n개`

### 공통 고지

- 결제 CTA 위와 결과 하단에 재미·참고용 콘텐츠 안내
- 태어난 시간 미상 결과에는 해석 제한 안내

### 캐릭터·문구

- 뿌기는 행운을 배달하다 명단을 잃어버린 거북이이며 12지 동물이 배달을 돕는 세계관을 사용한다.
- 로딩·빈 상태·완료 문구는 뿌기 또는 12지 동물의 행동으로 설명한다.
- 문구는 친근하고 응원하는 톤을 유지하며 불안 조장·합격 보장·의학적 단정을 금지한다.
- 캐릭터·부적·아이콘·로딩 스프라이트는 손그림 스타일로 제작한다.
- 🆕 카드·버튼 등 UI 테두리의 손그림 SVG 프레임(9-slice) 사용 여부는 `TBD(D-03)` — 디자인 미확정
- 🆕 결과 화면에서 운세를 전해주는 캐릭터는 `TBD(D-06)` — PD 제안: 결과는 뿌기가 전달, 부적에서 랜덤 동물 등장 ("뿌기가 토끼에게 배달을 부탁했어요")
- 반말/존댓말과 세부 캐릭터 보이스는 `TBD(D-05)`다.
- 생성형 AI 상담 채팅은 제공하지 않는다.

### 계산·콘텐츠 생성 원칙

- 사주 원국, 간지, 십성, 12운성, 합충형파해, 대운·세운은 오픈소스 만세력 라이브러리와 서버 계산 엔진으로만 계산한다.
- 서버는 계산 결과를 구조화된 JSON으로 정규화한 뒤 Liner API에 전달하고, Liner는 해당 데이터에 근거한 사용자용 사주 해석·설명 문장만 생성한다.
- Liner API는 원국·간지·십성·12운성·합충형파해·대운·세운을 직접 계산하지 않는다.
- 🆕 Liner 입력에는 계산 결과, 상품 유형, 기준일·이벤트 맥락, 선택형 질문 답변, **사용자가 입력한 고민**, 허용된 출력 섹션만 포함한다. 원본 생년월일시 등 문장 생성에 불필요한 개인정보는 제외한다.
- 🆕 ⚠️ 고민 입력은 결과 문구의 맥락으로만 쓰고 명리 값 계산에는 쓰지 않는다. 최대 100자, 금칙어 · 지시문(프롬프트 조작) · 연락처 등 개인정보 필터를 통과한 값만 전달한다. (BE-B 확정 필요)
- 계산 결과에 없는 명리 값을 AI가 추론하거나 보완하지 않도록 누락 필드와 허용 근거 키를 함께 전달한다. 응답이 허용된 섹션·근거 범위를 벗어나면 결과로 저장하지 않는다.
- 동일한 정규화 입력·상품·기준일·계산/생성 버전으로 이미 생성된 결과가 있으면 Liner를 다시 호출하지 않고 저장된 스냅샷을 반환한다. 🆕 고민 입력이 다르면 다른 결과 키로 본다.

## 3. 인증

### 로그인

1. 🆕 사용자가 카카오 · 네이버 · 구글 중 하나를 누른다.
2. 현재 복귀 경로를 안전한 내부 경로로 저장한다.
3. OAuth 완료 후 서버 세션 쿠키를 발급한다.
4. 🆕 본인 정보가 없으면 **로그인 직후 정보 입력(`HOME-02`)으로 이동**하고, 완료 후 복귀 경로로 돌아간다. 처음 가입한 사용자는 정보 입력 전에 ✚ 뿌기 스토리 온보딩을 볼 수 있다.
5. 🆕 비로그인 상태에서 홈의 기능 버튼을 누르면 로그인으로 이동한다. 선물 수신(`/g`), 공유 랜딩(`/share`), 정책 페이지는 로그인 없이 연다.

### 예외

- OAuth 취소: 로그인 화면에 취소 안내, 기존 입력 상태 유지
- 세션 만료: 로그인 후 원래 경로로 복귀
- 외부 URL을 복귀 경로로 사용할 수 없음
- 최대 5기기 초과 정책은 `TBD(I-02)`
- 🆕 같은 사람이 다른 소셜 계정으로 가입한 경우 계정 연결 여부는 `TBD(I-07)`

### 로그아웃·탈퇴

- 로그아웃은 현재 세션을 즉시 폐기한다.
- 탈퇴 전에 유료 등껍질 잔액과 환불 안내를 보여준다. (✚ 탈퇴 안내 모달)
- 탈퇴 요청 후 즉시 접근을 차단한다.

## 4. 인물 정보

### 입력 항목

| 필드 | 규칙 |
|---|---|
| 이름/닉네임 | 필수, 앞뒤 공백 제거 |
| 달력 | 양력/음력 필수 |
| 윤달 | 음력일 때만 노출 (🆕 와이어프레임 반영 필요) |
| 생년월일 | 1900-01-01~오늘, 필수 |
| 태어난 시간 | 시·분 또는 시간 모름 |
| 성별 | 남성/여성/선택하지 않음 |
| 관계 | 타인 저장 시 필수 (엄마 · 아빠 · 애인 · 직접 입력) |

### 동작

- 동일 생년정보가 있으면 중복 가능성을 알리되 저장할 수 있다.
- 타인 저장은 최대 10명이다.
- 궁합 상대는 저장 인물을 불러오거나 새로 입력할 수 있다.
- 타인 정보 입력 권한 확인 체크가 필수다. (🆕 와이어프레임 반영 필요)
- 운영자는 생년정보를 직접 수정할 수 없다.

## 5. 홈

- 오늘의 운세, 일반 운세 5종(종합·애정·재물·궁합·신살), 수능운, 선물하기를 노출한다.
- 🆕 로그인 상태에서는 상단에 등껍질 잔액을 표시하고, 누르면 `/wallet`로 이동한다.
- 판매 종료 상품은 비활성 상태와 안내 문구를 표시한다.
- 수능 종료 후 수능운 신규 구매 CTA를 숨기고 결과 보관함 접근만 유지한다.
- 세계관 소개는 핵심 CTA를 밀어내지 않는 짧은 문구·캐릭터 연출로 제한한다.

## 6. 오늘의 무료 운세

### 흐름

1. 🆕 로그인 · 본인 정보 입력이 끝난 사용자만 이용한다.
2. 저장된 본인 정보로 당일 결과를 요청한다.
3. 로딩(`TODAY-01`) 후 결과(`TODAY-02`)를 표시한다.
4. 결과·공유·유료 상품 CTA(`내 운세 더 자세히 보기`)를 표시한다.

- 🆕 v0.2의 비로그인 입력 · localStorage 30일 보관 흐름은 삭제한다.

### 결과

- 한줄 운세, 운세 지수, 행운 색, 행운 아이템, 행운 장소, 오늘의 행동
- 같은 정규화 인물정보·날짜에는 같은 결과
- 재조회 가능, 재추첨 불가
- 분석 전/중에는 엎드린 거북이 또는 등껍질 연출, 완료 후에는 일어난 뿌기 연출을 사용한다.
- 공유하기는 ✚ 공유 랜딩(`/share/[shareId]`)으로 연결한다.

## 7. 등껍질 충전

### 진입

- 🆕 홈 상단 잔액, 마이페이지, 유료 구매 · 선물의 잔액 부족 모달
- 잔액 부족 모달은 부족 수량과 가장 가까운 충전 상품을 강조한다.

### 충전 상품

| 유료 | 보너스 | 총 지급 | 가격 |
|---:|---:|---:|---:|
| 10 | 0 | 10 | 1,000원 |
| 30 | 3 | 33 | 3,000원 |
| 50 | 6 | 56 | 5,000원 |
| 100 | 14 | 114 | 10,000원 |
| 300 | 46 | 346 | 30,000원 |
| 500 | 🆕 80 | 🆕 580 | 50,000원 |

- 상품 카드에는 `유료 + 보너스`, 총 지급량, 원화 가격을 모두 표시한다. 1,000원 상품은 보너스가 없다.
- 충전 완료 시 유료 등껍질과 보너스 등껍질을 별도 원장 항목으로 기록한다.
- 🆕 차감 순서(P-02A): 유효기간이 빨리 끝나는 지급분 → 같으면 보너스 먼저 → 먼저 지급된 순
- 🆕 유효기간: 유료 등껍질 지급일로부터 5년, 보너스 등껍질 지급일로부터 1년 (토스 상담 후 최종 확인)
- 🆕 충전 화면 결제 버튼 근처에 유효기간, `결제 승인 즉시 지급`, 환불정책 링크를 표시한다. (PG 심사)

### 흐름

1. 서버에서 활성 충전 상품과 가격을 조회한다.
2. 상품 선택 후 토스페이먼츠 결제창을 연다.
3. 성공 URL에서 서버 승인 요청을 보낸다.
4. 승인 완료 후 충전 원장을 기록하고 잔액을 갱신한다.
5. 구매 중이었다면 30분 내 저장된 상태로 복귀한다. (`충전 완료! 이어서 볼까요?` 팝업)

### 상태

`CREATED → PAYMENT_PENDING → PAID → CREDITED`

예외 상태: `FAILED`, `CANCELED`, `REFUNDED`. `PAID` 후 `CREDITED` 실패는 서버 재시도하며 중복 지급하지 않는다.

## 9. 부적

### 🆕 생성 규칙

- 부적은 **고르지 않는다.** 운세 결과의 **부족한 기운**을 기준으로 자동생성한다.
- 조합 요소

| 요소 | 결정 방식 | 종류 |
|---|---|---|
| 색 · 프레임 색 | 부족한 오행 | 5종 (목 · 화 · 토 · 금 · 수) |
| 동물 | **12지 중 랜덤** | 12종 |
| 문구 | 운세 × 오행별로 미리 써둔 문구 풀에서 서버가 선택 | PD 작성 |

- 같은 운세를 다른 날 사면 부족한 기운 · 문구 · 동물이 달라질 수 있다.
- 부적 화면에 "~ 기운이 부족해서 ~색을 넣었어요" 같은 부적 설명을 표시한다.
- 구매 · 선물 · 부적 추가 구매 요청에 `talismanType`을 받지 않는다. 응답에 생성된 부적 정보(오행 · 동물 · 문구)를 포함한다.
- 띠 경계 기준(T-02)은 부적 동물에는 적용하지 않는다.
- 이미지에 이름·생년월일·성별을 넣지 않는다.

### 열람·저장·공유

- 원본 1080×1920 PNG, 썸네일 360×640 WebP
- 원본은 권한 확인 후 10분 signed URL로 제공한다.
- iOS는 직접 다운로드가 제한되면 길게 눌러 저장 안내를 제공한다.
- 공유 이미지는 개인정보가 없는 별도 에셋을 사용한다.
- 개인 사주 결과와 부적에는 카카오톡 공유하기를 제공한다.
- 공유 payload에는 생년월일시·성별을 넣지 않는다. 공유할 결과 범위와 카드 구성은 `TBD(G-11)`에 따르며 부적은 개인정보 없는 공유용 이미지를 사용한다.
- 공유 시 서버에서 비식별 공유 리소스를 만든 뒤 Kakao JavaScript SDK의 공유하기를 호출한다.
- 🆕 공유 랜딩(`/share/[shareId]`): 캐릭터 + 결과 요약 카드(운세 제목 · 캐릭터 이미지) + `나도 보러 가기` CTA. 상세 결과 · 생년정보 · 선물 메시지는 노출하지 않는다.

### 부적 창고

- 구매·선물 부적을 통합 표시한다.
- 🆕 **같은 동물**끼리 `×N`으로 묶고, 상세에서 각 부적과 획득 이력을 펼쳐 본다.
- 🆕 12지 도감 진행도(예: 3/12)를 표시한다. 동물이 랜덤이라 수집 동기로 쓴다. 완성 보상은 없다.

## 10. 선물 구매

### 🆕 범위 · 가격

- 1차 출시 선물은 **수능운만** 가능하다.
- 선물도 **등껍질로 결제**한다. 원화 결제는 충전뿐이다.

| 옵션 | 등껍질 | 코드 |
|---|---:|---|
| 부적만 | 10개 | `TALISMAN_ONLY` |
| 사주 + 부적 | 15개 | `READING_WITH_TALISMAN` |

### 🆕 위저드 단계

1. 옵션 선택 (`GIFT-01`)
2. 수신자 이름/닉네임과 알림톡 수신 휴대전화번호 입력 + 개인정보 동의 (`GIFT-02`)
3. 메시지 카드: 보내는 사람 이름(카카오 닉네임 기본값) + 편지 (`GIFT-03`)
4. 등껍질 차감 확인 팝업 (잔액 부족 → 충전 → 복귀)

- ~~운세 유형 선택~~ · ~~부적 선택~~ 단계 삭제
- ⚠️ 여러 명에게 선물하기(`GIFT-06~08`, 메시지 공통/개별)는 팀 확정 필요. 하는 경우 내부적으로 수신자 수만큼 선물 n건을 한 번에 주문하는 방식 제안
- 위저드 상태는 Zustand + sessionStorage에 보관한다.
- 메시지는 200자, 이모지·줄바꿈 허용, 금칙어 검사, HTML 이스케이프한다.
- `부적` 선물은 부적과 편지, 수능 체크리스트를 제공한다.
- `부적+사주` 선물은 부적·편지·사주 결과와 수능 체크리스트를 제공한다.

### 결제 완료

- 🆕 등껍질 차감 완료 후에만 선물과 링크를 활성화한다.
- 서비스가 수신자 휴대전화번호로 선물 링크를 포함한 카카오 알림톡을 발송한다.
- 🆕 알림톡 정책(G-10): 자동 재시도 3회(1 · 5 · 30분), 수동 재발송 하루 3회 · 1분 간격(KST 자정 초기화), **SMS 대체 없음**, 번호 수정은 CS. 대행사는 미정.
- 🆕 재발송하면 새 링크를 발급하고 이전 링크는 폐기한다. 재발송 확인 모달에 "다시 보내면 이전에 보낸 링크는 더 이상 열리지 않아요" 안내를 표시한다.
- 완료 화면(`GIFT-04`)에 알림톡 발송 상태를 표시한다.
- 🆕 ⚠️ 발송 실패 화면(`GIFT-05`)의 `링크 직접 공유`는 BE의 원문 링크 삭제 정책과 맞는지 BE 확인 필요
- 알림톡 발송 실패 시 선물을 자동 취소하지 않는다.
- 수신자 전화번호는 화면·로그·Sentry·PostHog에서 마스킹하며 보관기간은 `TBD(G-10A)`다.

## 11. 선물 수신

### 토큰 진입

- 토큰이 없거나 폐기·만료·취소됐으면 선물 정보를 노출하지 않고 ✚ 열 수 없는 링크 안내를 보여준다.
- 유효한 미사용 링크는 수신자 이름, 보낸 사람 이름, 상품 종류를 표시한다.
- 🆕 도착 화면(`RECV-01`)은 뿌기가 부적을 들고 온 연출을 쓴다. (부적 동물은 랜덤이라 띠 전환 연출 없음)
- 🆕 OG에는 수신자 이름과 보낸 사람 이름을 노출하고, 선물 메시지 · 생년정보는 넣지 않는다.

### 정보 제출

- 수신자가 자신의 생년월일시(양력/음력)·성별을 입력한다. (`RECV-02`)
- 🆕 생년정보 수집 동의 체크를 받는다.
- 한 번 제출하면 잠기고 수정 UI를 제공하지 않는다.
- 오류 시 CS 초기화 안내를 제공한다.

### 결과 공개

- 메시지 확인(`RECV-03`) 후 옵션에 따라 공개한다.
  - 사주 + 부적: 교시별 사주 → 수능 도시락 → 준비물 체크리스트 → 수능 부적 (`RECV-04~07`)
  - 부적만: 수능 부적 (`RECV-T-04`)
- 결과 생성이 완료되면 단건 선물 전체를 즉시 공개한다.

### 재열람·계정 연결

- 🆕 링크를 다시 열면 정보 입력 없이 결과로 바로 이동한다.
- 🆕 링크 만료(G-07): 미사용 링크는 결제 후 90일, 사용 후 재열람은 첫 콘텐츠 조회부터 90일. 만료 직전 입력했다면 첫 조회까지 24시간 유예. 만료돼도 자동 환불 · 연장 없음, CS 접수.
- 로그인 시 부적 창고와 계정에 연결할 수 있다.
- 결과 하단에 `다른 운세도 보러가기` CTA를 제공해 로그인 → 홈으로 연결한다.
- 🆕 PD 제안: `나도 친구에게 선물하기` CTA 추가, 가입 시 입력한 생년정보 이어받기 (BE 확인 필요)

## 15. 상태 모델

### 본인 구매

`CREATED → DEBITED → GENERATING → FULFILLED`

- 실패: `FAILED → REFUNDED`
- 같은 멱등키의 재요청은 최초 상태와 결과를 반환한다.

### 🆕 선물 주문

`CREATED → DEBITED → ACTIVE → COMPLETED`

- 취소: `CANCELED → REFUNDED` (등껍질 환급)

### 알림톡 발송

`PENDING → SENT | FAILED`

- 동일 선물·동일 발송 목적의 중복 발송을 막는 멱등 키를 사용한다.
- 🆕 자동 재시도 3회, SMS 대체 없음 (G-10)

### 선물 수신

`UNCLAIMED → RECIPIENT_SUBMITTED → ACTIVE → COMPLETED → EXPIRED`

- 토큰 재발급 시 기존 링크는 `REVOKED`

### 부적

`PENDING → READY | FAILED`

- 동기/비동기 생성 방식은 `TBD(F-06)`

## 17. 접근성·검증

- 버튼·링크에 접근 가능한 이름을 제공한다.

## 18. 출시 E2E 시나리오

1. 🆕 소셜 로그인(3종 각각) → 정보 입력 → 충전 → 일반 운세 사주+부적 → 저장
2. 소셜 로그인 → 수능운 구매 → 결과 전 섹션 → 재열람
3. 🆕 선물 단건 **등껍질 결제** → 알림톡 발송 → 다른 기기 비로그인 수신 → 결과
4. 결제 승인 재전송 → 중복 결제·지급 없음
5. 결과 생성 실패 → 등껍질 자동 환급
6. 토큰 한 글자 변조 → 정보 미노출
7. 탈퇴 → 접근 차단 → 삭제·법정 보관 분리
8. 🆕 사주만 구매 → 결과에서 부적 추가 구매(10개) → 부적 창고 도감 반영
