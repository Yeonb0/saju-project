## 1. 공통 규칙

### 지원 환경

- 모바일 웹 우선, 앱 기둥 최대 폭 402px
- iOS Safari, Android Chrome, 카카오톡 인앱브라우저
- `100dvh`, safe-area 반영
- 날짜·D-day·콘텐츠 공개는 `Asia/Seoul`

### 공통 UI

- `AppShell`: 헤더, 뒤로가기, 메뉴, 본문, 하단 고정 CTA
- 뒤로가기는 브라우저 기록이 아닌 명시적 라우트 링크를 기본으로 한다.
- 🆕 사이드 메뉴(`HOME-04`): 홈, 마이페이지, 내 부적 창고, 오늘의 운세, 유료 운세, 수능운
- 비동기 화면은 로딩·빈 상태·실패·재시도 상태를 모두 제공한다.
- 결제·재화·선물 CTA는 처리 중 중복 입력을 막는다.
- 모든 금액·재화 차감량은 서버 응답을 표시한다.
- 🆕 재화 표기 단위는 `등껍질 n개`

### 공통 고지

- 결제 CTA 위와 결과 하단에 재미·참고용 콘텐츠 안내 — 🆕4 문구 「운세와 부적은 재미와 참고를 위한 콘텐츠예요.」 (`FORT-02 · 03 · MATCH-03 질문_수정안`)
- 태어난 시간 미상 결과에는 해석 제한 안내

### 캐릭터·문구

- 뿌기는 행운을 배달하다 명단을 잃어버린 거북이이며 12지 동물이 배달을 돕는 세계관을 사용한다.
- 로딩·빈 상태·완료 문구는 뿌기 또는 12지 동물의 행동으로 설명한다.
- 문구는 친근하고 응원하는 톤을 유지하며 불안 조장·합격 보장·의학적 단정을 금지한다.
- 캐릭터·부적·아이콘·로딩 스프라이트는 손그림 스타일로 제작한다.
- 🆕4 카드 · 버튼 · 팝업 · 칩 · 태그의 손그림 외곽선은 사용한다 (D-03 확정). FE 가 구현하고, 크기가 고정된 장식(리본 · 부적 틀 등)만 PD 가 SVG 로 준다.
- 🆕 결과 화면에서 운세를 전해주는 캐릭터는 `TBD(D-06)` — PD 제안: 결과는 뿌기가 전달, 부적에서 랜덤 동물 등장 ("뿌기가 토끼에게 배달을 부탁했어요")
- 🆕4 말투 (D-05 확정): 뿌기 · 12지 말풍선 · 메모지는 반말, 그 밖의 서비스 문구는 해요체.
- 생성형 AI 상담 채팅은 제공하지 않는다.

### 계산·콘텐츠 생성 원칙

- 사주 원국, 간지, 십성, 12운성, 합충형파해, 대운·세운은 오픈소스 만세력 라이브러리와 서버 계산 엔진으로만 계산한다.
- 서버는 계산 결과를 구조화된 JSON으로 정규화한 뒤 Liner API에 전달하고, Liner는 해당 데이터에 근거한 사용자용 사주 해석·설명 문장만 생성한다.
- Liner API는 원국·간지·십성·12운성·합충형파해·대운·세운을 직접 계산하지 않는다.
- 🆕4 Liner 입력에는 계산 결과, 상품 유형, 기준일·이벤트 맥락, 선택형 질문 답변, 허용된 출력 섹션만 포함한다. 원본 생년월일시 등 문장 생성에 불필요한 개인정보는 제외한다.
- 🆕4 1차에는 자유 메모 · 고민 입력 칸을 두지 않고 서버 · Liner 로 수집 · 전송하지 않는다 (F-04 확정, 개인정보처리방침에 수집 항목 없음). 2차에 도입하면 개인정보처리방침, 100자 · 금칙어 · 연락처 · 프롬프트 조작 필터, 결과 재사용 키, Liner 전송 범위를 함께 바꾼다.
- 계산 결과에 없는 명리 값을 AI가 추론하거나 보완하지 않도록 누락 필드와 허용 근거 키를 함께 전달한다. 응답이 허용된 섹션·근거 범위를 벗어나면 결과로 저장하지 않는다.
- 동일한 정규화 입력·상품·기준일·계산/생성 버전으로 이미 생성된 결과가 있으면 Liner를 다시 호출하지 않고 저장된 스냅샷을 반환한다.

## 3. 인증

### 로그인

1. 🆕4 사용자가 「카카오로 계속하기」를 누른다. 버튼 아래 안내: 「사주를 보기 위해서는 로그인이 필요해요!」 (`HOME-01 로그인_수정안`). 1차는 카카오만, 네이버 · 구글은 2차 (A-01). 정책 문서 표기는 「회사가 제공하는 소셜 계정(현재 카카오)」 (Q-43).
2. 현재 복귀 경로를 안전한 내부 경로로 저장한다.
3. OAuth 완료 후 서버 세션 쿠키를 발급한다.
4. 🆕 본인 정보가 없으면 **로그인 직후 정보 입력(`HOME-02`)으로 이동**하고, 완료 후 복귀 경로로 돌아간다. 처음 가입한 사용자는 정보 입력 전에 ✚ 뿌기 스토리 온보딩을 볼 수 있다.
5. 🆕 비로그인 상태에서 홈의 기능 버튼을 누르면 로그인으로 이동한다. 선물 수신(`/g`), 공유 랜딩(`/share`), 정책 페이지는 로그인 없이 연다.

### 예외

- OAuth 취소: 로그인 화면에 취소 안내, 기존 입력 상태 유지 — 🆕4 문구 「로그인을 취소했어요. 다시 시도해 주세요.」
- 🆕4 OAuth 실패: 「로그인 중 문제가 생겼어요. 잠시 후 다시 시도해 주세요.」
- 세션 만료: 로그인 후 원래 경로로 복귀
- 외부 URL을 복귀 경로로 사용할 수 없음
- 최대 5기기 초과 정책은 `TBD(I-02)`
- 🆕 같은 사람이 다른 소셜 계정으로 가입한 경우 계정 연결 여부는 `TBD(I-07)`

### 로그아웃·탈퇴

- 로그아웃은 현재 세션을 즉시 폐기한다.
- 🆕4 탈퇴 안내는 `MY-07 회원탈퇴 안내` 화면이다. 남은 등껍질(유료 · 보너스)과 구매한 운세 · 부적 수를 서버 값으로 보여준다.
- 🆕4 남은 유료 등껍질이 있으면 탈퇴할 수 없다 (약관 11조 · 서버 `PAID_BALANCE_REMAINS`). 이때 「탈퇴하기」는 비활성이다 (Q-52).
- 🆕4 `MY-07` 안내 문구:

## 7. 등껍질 충전

### 진입

- 🆕 홈 상단 잔액, 마이페이지, 유료 구매 · 선물의 잔액 부족 모달
- 잔액 부족 모달은 부족 수량과 가장 가까운 충전 상품을 강조한다.

### 충전 상품

| 유료 | 보너스 | 총 지급 | 가격 |
|---:|---:|---:|---:|
| 10 | 0 | 10 | 1,000원 |
| 30 | 3 | 33 | 3,000원 |
| 50 | 6 | 56 | 5,000원 |
| 100 | 14 | 114 | 10,000원 |
| 300 | 46 | 346 | 30,000원 |
| 500 | 🆕 80 | 🆕 580 | 50,000원 |

- 상품 카드에는 `유료 + 보너스`, 총 지급량, 원화 가격을 모두 표시한다. 1,000원 상품은 보너스가 없다.
- 충전 완료 시 유료 등껍질과 보너스 등껍질을 별도 원장 항목으로 기록한다.
- 🆕 차감 순서(P-02A): 유효기간이 빨리 끝나는 지급분 → 같으면 보너스 먼저 → 먼저 지급된 순
- 🆕 유효기간: 유료 등껍질 지급일로부터 5년, 보너스 등껍질 지급일로부터 1년 (토스 상담 후 최종 확인)
- 🆕 충전 화면 결제 버튼 근처에 유효기간, `결제 승인 즉시 지급`, 환불정책 링크를 표시한다. (PG 심사)

### 🆕4 충전 화면 (`PAY-01 등껍질 충전_수정안`)

- 결제 수단 칸은 없다. 「N원 결제하기」를 누르면 바로 토스 결제창을 연다.
- 안내 상자 (결제하기 위):

```
· 등껍질은 결제 승인 즉시 지급돼요. 유효기간은 유료 5년, 보너스 1년이에요.
· 유효기간이 먼저 끝나는 등껍질부터 사용돼요.
· 충전 후 7일 이내, 그 충전의 등껍질을 하나도 쓰지 않았다면 고객센터로 신청해 전액 환불받을 수 있어요.
· 남은 유료 등껍질 환불도 고객센터 이메일로 신청해 주세요.
· 미성년자는 법정대리인 동의를 받아 결제해 주세요. 동의 없이 결제하면 취소될 수 있어요.
· 환불정책 보기 >
```

- ⚠️ 첫 줄 「결제 승인 즉시 지급돼요」는 정책 v3 에서 「승인 확인 후 지급」으로 바뀔 수 있다 (Q-56, BE-A 요청). 바뀌면 이 줄도 같이 바꾼다.
- 동의 체크 (필수): 「주문 내용과 환불정책을 확인했으며 결제에 동의합니다. (필수)」. 체크 전에는 「결제하기」가 비활성이다. 토스 결제창 안의 동의(결제 서비스 약관)와 역할이 다르다 — 이 체크는 디지털 콘텐츠 청약철회 제한 · 환불정책 고지다 (Q-25).
- 충전 환불은 화면 없이 고객센터 이메일로만 받는다. 사용자 환불 신청 버튼 · 화면은 만들지 않는다 (Q-41 · Q-42).
- 잔액 부족으로 들어오면 상단에 부족 수량 + 추천 상품 강조 (`PAY-02`, 서버 견적 값).
- 판매 중인 충전 상품이 없으면 `PAY-06`: 「지금은 충전할 수 있는 상품이 없어요」 / 「잠시 후 다시 확인해 주세요.」 / 「홈으로」.

### 흐름

1. 서버에서 활성 충전 상품과 가격을 조회한다.
2. 상품 선택 후 토스페이먼츠 결제창을 연다.
3. 성공 URL에서 서버 승인 요청을 보낸다.
4. 승인 완료 후 충전 원장을 기록하고 잔액을 갱신한다.
5. 구매 중이었다면 30분 내 저장된 상태로 복귀한다. (`충전 완료! 이어서 볼까요?` 팝업)

### 🆕4 결제 결과 화면

| 화면 | 상황 | 문구 · 버튼 |
|---|---|---|

`CREATED → PAYMENT_PENDING → PAID → CREDITED`

예외 상태: `FAILED`, `CANCELED`, `REFUNDED`, 🆕4 `REFUND_PENDING`(환불 처리 중), `PARTIALLY_REFUNDED`(잔여 유료분 환불 완료). `PAID` 후 `CREDITED` 실패는 서버 재시도하며 중복 지급하지 않는다. 환불 상태 표시는 12장 `MY-03`.

- 🆕 질문 화면 하단 옵션 버튼으로 선택한다: `사주 보고 부적도 받기 (15개, 정가 20개)` / `사주만 보기 (10개)`

### 🆕4 구매 상태 화면 (`COMMON-02 ~ 04`, Q-40)

화면 분기는 서버 구매 `status`, 버튼은 `nextAction` 을 따른다.

### 결과

- 로딩 화면 후 `calculationVersion`, `generationVersion`, `contentVersion`과 함께 저장된 결과 스냅샷을 표시한다.

- 섹션 간 이동 상태는 URL 또는 결과 내부 상태로 보존한다.
- 🆕 공통 결과 구조: **요약 → 소제목 + 내용 (반복) → 나에게 부족한 기운 → 부적**

  - 수능 부적 (구매에 포함)

- 잔액 부족: 충전 안내
- 잘못된 입력: 해당 필드로 이동
- 생성 실패: 차감 복구 상태와 재시도 안내 (🆕4 위 구매 상태 화면 `RETRY_PURCHASE`)
- Liner 시간 초과·호출 실패·응답 검증 실패: 서버 내부 제한 횟수만 재시도하고 최종 실패 시 구매 실패 및 등껍질 자동 환급
- 중복 요청: 최초 구매 결과로 이동
- 권한 없음: 403 화면

## 9. 부적

### 🆕 생성 규칙

- 부적은 **고르지 않는다.** 운세 결과의 **부족한 기운**을 기준으로 자동생성한다.
- 조합 요소

| 요소 | 결정 방식 | 종류 |
|---|---|---|
| 색 · 프레임 색 | 부족한 오행 | 5종 (목 · 화 · 토 · 금 · 수) |
| 동물 | **12지 중 랜덤** | 12종 |
| 문구 | 운세 × 오행별로 미리 써둔 문구 풀에서 서버가 선택 | PD 작성 |

- 같은 운세를 다른 날 사면 부족한 기운 · 문구 · 동물이 달라질 수 있다.
- 부적 화면에 "~ 기운이 부족해서 ~색을 넣었어요" 같은 부적 설명을 표시한다.
- 구매 · 선물 · 부적 추가 구매 요청에 `talismanType`을 받지 않는다. 응답에 생성된 부적 정보(오행 · 동물 · 문구)를 포함한다.
- 띠 경계 기준(T-02)은 부적 동물에는 적용하지 않는다.
- 이미지에 이름·생년월일·성별을 넣지 않는다.

### 열람·저장·공유

- 원본 1080×1920 PNG, 썸네일 360×640 WebP
- 원본은 권한 확인 후 10분 signed URL로 제공한다.
- iOS는 직접 다운로드가 제한되면 길게 눌러 저장 안내를 제공한다.
- 공유 이미지는 개인정보가 없는 별도 에셋을 사용한다.
- 개인 사주 결과와 부적에는 카카오톡 공유하기를 제공한다.
- 공유 payload에는 생년월일시·성별을 넣지 않는다. 오늘의 운세는 날짜·지수 5개·한줄 운세·행운 항목의 비식별 스냅샷만 24시간 공개하고 생성자가 철회할 수 있다. 일반 결과·부적 카드 구성은 `TBD(G-11)`이며 부적은 개인정보 없는 공유용 이미지를 사용한다.
- 공유 시 서버에서 비식별 공유 리소스를 만든 뒤 Kakao JavaScript SDK의 공유하기를 호출한다.
- 🆕 공유 랜딩(`/share/[shareId]`): 캐릭터 + 결과 요약 카드(운세 제목 · 캐릭터 이미지) + `나도 보러 가기` CTA. 상세 결과 · 생년정보 · 선물 메시지는 노출하지 않는다.

### 부적 창고

- 구매·선물 부적을 통합 표시한다.
- 🆕 **같은 동물**끼리 `×N`으로 묶고, 상세에서 각 부적과 획득 이력을 펼쳐 본다.
- 🆕 12지 도감 진행도(예: 3/12)를 표시한다. 동물이 랜덤이라 수집 동기로 쓴다. 완성 보상은 없다.

## 10. 선물 구매

> 2026-10-14 사용자 개발 지시로 1차 직접 공유·알림톡 2차 기준을 반영했다. 정책 v2 원문은 아직 알림톡이므로 PD 정책 v3와 최종 화면 문구 반영은 필요하다. A의 공개 응답 계약은 gift OpenAPI를 따른다.

### 🆕 범위 · 가격

- 1차 출시 선물은 **수능운만** 가능하다.
- 선물도 **등껍질로 결제**한다. 원화 결제는 충전뿐이다.

| 옵션 | 등껍질 | 코드 |
|---|---:|---|
| 부적만 | 10개 | `TALISMAN_ONLY` |
| 사주 + 부적 | 15개 | `READING_WITH_TALISMAN` |

### 🆕 위저드 단계

1. 옵션 선택 (`GIFT-01`)
2. 수신자 이름/닉네임 입력 (`GIFT-02`). 1차에는 전화번호를 받지 않는다. 실제 수집 항목의 동의·고지는 정책 v3에 맞춘다.
3. 메시지 카드: 보내는 사람 이름(카카오 닉네임 기본값) + 편지 (`GIFT-03`)
4. 등껍질 차감 확인 팝업 (잔액 부족 → 충전 → 복귀)

- ~~운세 유형 선택~~ · ~~부적 선택~~ 단계 삭제
- ⚠️ 여러 명에게 선물하기(`GIFT-06~08`, 메시지 공통/개별)는 팀 확정 필요. 하는 경우 내부적으로 수신자 수만큼 선물 n건을 한 번에 주문하는 방식 제안
- 위저드 상태는 Zustand + sessionStorage에 보관한다.
- 메시지는 200자, 이모지·줄바꿈 허용, 금칙어 검사, HTML 이스케이프한다.
- `부적` 선물은 부적과 편지, 수능 체크리스트를 제공한다.
- `부적+사주` 선물은 부적·편지·사주 결과와 수능 체크리스트를 제공한다.

### 결제 완료

- 🆕 등껍질 차감 완료 후에만 선물과 링크를 활성화한다.
- 구매자가 서버가 준 `/g#token=...` 링크를 복사하거나 카카오톡 공유하기로 직접 전달한다. 신규 주문에 알림톡 발송/재시도는 없다.
- `GIFT-04`는 구매 완료와 링크 복사/공유를 보여준다. 링크를 복사/공유한 것이 수신자 열람이나 콘텐츠 제공 완료를 뜻하지 않는다. 최종 화면 문구는 PD 확인이 필요하다.
- 원문 링크 조회기간은 발급부터 24시간이다. 조회기간 종료 시 `shareUrl=null`이며 기존 수신 권한 90일이 종료됐다는 뜻은 아니다.
- 재발급은 실제 구매 차감부터 30일 미만, 주문별 KST 하루 3회, 1분 간격이다. FE는 서버 `canReissue`, `remainingReissues`, `nextReissueAt`를 따른다. 자정에도 1분 간격은 유지한다.
- 재발급하면 이전 링크를 폐기하고 사용 기한은 연장하지 않는다. 같은 요청 키 replay는 추가 재발급/횟수 사용을 하지 않으며, 더 최신 재발급이 있으면 이전 요청 응답의 `shareUrl`은 null이다. 현재 링크는 별도 조회한다.
- 알림톡·전화번호 수집/정리는 2차 범위이며 기존 발송 기반은 비활성으로 보존한다. 링크 조회/공유 실패만으로 선물을 자동 취소하지 않는다.

## 11. 선물 수신

### 토큰 진입

- 토큰이 없거나 폐기·만료·취소됐으면 선물 정보를 노출하지 않고 ✚ 열 수 없는 링크 안내를 보여준다.
- 유효한 미사용 링크는 수신자 이름, 보낸 사람 이름, 상품 종류를 표시한다.
