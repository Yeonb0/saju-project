## 1. 공통 규칙

### 지원 환경

- 모바일 웹 우선, 앱 기둥 최대 폭 402px
- iOS Safari, Android Chrome, 카카오톡 인앱브라우저
- `100dvh`, safe-area 반영
- 날짜·D-day·콘텐츠 공개는 `Asia/Seoul`

### 공통 UI

- `AppShell`: 헤더, 뒤로가기, 메뉴, 본문, 하단 고정 CTA
- 뒤로가기는 브라우저 기록이 아닌 명시적 라우트 링크를 기본으로 한다.
- 사이드 메뉴: 홈, 마이페이지, 내 부적 창고, 오늘의 운세, 유료 운세
- 비동기 화면은 로딩·빈 상태·실패·재시도 상태를 모두 제공한다.
- 결제·재화·선물 CTA는 처리 중 중복 입력을 막는다.
- 모든 금액·재화 차감량은 서버 응답을 표시한다.

### 공통 고지

- 결제 CTA 위와 결과 하단에 재미·참고용 콘텐츠 안내
- 태어난 시간 미상 결과에는 해석 제한 안내

### 캐릭터·문구

- 뿌기는 행운을 배달하다 명단을 잃어버린 거북이이며 12지 동물이 배달을 돕는 세계관을 사용한다.
- 로딩·빈 상태·완료 문구는 뿌기 또는 해당 띠 동물의 행동으로 설명한다.
- 문구는 친근하고 응원하는 톤을 유지하며 불안 조장·합격 보장·의학적 단정을 금지한다.
- 캐릭터·UI·부적·아이콘·로딩 스프라이트는 도트(픽셀) 스타일로 제작한다.
- 래스터 픽셀 에셋은 정수 배율과 `image-rendering: pixelated`를 사용한다.
- 반말/존댓말과 세부 캐릭터 보이스는 `TBD(D-05)`다.
- 생성형 AI 상담 채팅은 제공하지 않는다.

### 계산·콘텐츠 생성 원칙

- 사주 원국, 간지, 십성, 12운성, 합충형파해, 대운·세운은 오픈소스 만세력 라이브러리와 서버 계산 엔진으로만 계산한다.
- 서버는 계산 결과를 구조화된 JSON으로 정규화한 뒤 Liner API에 전달하고, Liner는 해당 데이터에 근거한 사용자용 사주 해석·설명 문장만 생성한다.
- Liner API는 원국·간지·십성·12운성·합충형파해·대운·세운을 직접 계산하지 않는다.
- Liner 입력에는 계산 결과, 상품 유형, 기준일·이벤트 맥락, 선택형 관심 항목, 허용된 출력 섹션만 포함한다. 원본 생년월일시 등 문장 생성에 불필요한 개인정보는 제외한다.
- 계산 결과에 없는 명리 값을 AI가 추론하거나 보완하지 않도록 누락 필드와 허용 근거 키를 함께 전달한다. 응답이 허용된 섹션·근거 범위를 벗어나면 결과로 저장하지 않는다.
- 동일한 정규화 입력·상품·기준일·계산/생성 버전으로 이미 생성된 결과가 있으면 Liner를 다시 호출하지 않고 저장된 스냅샷을 반환한다.
- 자유 메모는 화면 표시 용도로만 저장하며 계산 입력이나 Liner 생성 맥락으로 사용하지 않는다.

## 3. 인증

### 로그인

1. 사용자가 카카오 로그인 버튼을 누른다.
2. 현재 복귀 경로를 안전한 내부 경로로 저장한다.
3. 카카오 OAuth 완료 후 서버 세션 쿠키를 발급한다.
4. 신규 사용자도 홈 탐색·선물 구매 시 온보딩을 강제하지 않는다.
5. 본인 운세 구매 시 본인 정보가 없으면 정보 입력으로 이동한다.

### 예외

- OAuth 취소: 로그인 화면에 취소 안내, 기존 입력 상태 유지
- 세션 만료: 로그인 후 원래 경로로 복귀
- 외부 URL을 복귀 경로로 사용할 수 없음
- 최대 5기기 초과 정책은 `TBD(I-02)`

### 로그아웃·탈퇴

- 로그아웃은 현재 세션을 즉시 폐기한다.
- 탈퇴 전에 유료 등껍질 잔액과 환불 안내를 보여준다.
- 탈퇴 요청 후 즉시 접근을 차단한다.

## 4. 인물 정보

### 입력 항목

| 필드 | 규칙 |
|---|---|
| 이름/닉네임 | 필수, 앞뒤 공백 제거 |
| 달력 | 양력/음력 필수 |
| 윤달 | 음력일 때만 노출 |
| 생년월일 | 1900-01-01~오늘, 필수 |
| 태어난 시간 | 시·분 또는 시간 모름 |
| 성별 | 남성/여성/선택하지 않음 |
| 관계 | 타인 저장 시 필수 |

### 동작

- 동일 생년정보가 있으면 중복 가능성을 알리되 저장할 수 있다.
- 타인 저장은 최대 10명이다.
- 궁합 상대는 저장 인물을 불러오거나 새로 입력할 수 있다.
- 타인 정보 입력 권한 확인 체크가 필수다.
- 운영자는 생년정보를 직접 수정할 수 없다.

## 5. 홈

- 오늘의 운세, 일반 운세 5종(종합·애정·재물·궁합·신살), 수능운, 선물하기를 노출한다.
- 판매 종료 상품은 비활성 상태와 안내 문구를 표시한다.
- 수능 종료 후 수능운 신규 구매 CTA를 숨기고 결과 보관함 접근만 유지한다.
- 로그인 상태에서는 등껍질 잔액과 최근 결과 진입점을 제공할 수 있다.
- 세계관 소개는 핵심 CTA를 밀어내지 않는 짧은 문구·캐릭터 연출로 제한한다.

## 6. 오늘의 무료 운세

### 흐름

1. 저장된 로컬 정보가 있으면 불러오기 여부를 제공한다.
2. 비로그인 인물 정보를 입력한다.
3. 정보 저장 동의 시 localStorage에 값과 `expiresAt`을 저장한다.
4. 당일 결과를 요청한다.
5. 결과·공유·유료 상품 CTA를 표시한다.

### 결과

- 한줄 운세, 행운 색, 행운 아이템, 행운 장소, 오늘의 행동
- 같은 정규화 인물정보·날짜에는 같은 결과
- 재조회 가능, 재추첨 불가
- localStorage 보관기간 30일, 만료 시 삭제
- 분석 전/중에는 엎드린 거북이 또는 등껍질 연출, 완료 후에는 일어난 뿌기 연출을 사용한다.

## 7. 등껍질 충전

### 진입

- 지갑 화면 또는 유료 구매의 잔액 부족 모달
- 잔액 부족 모달은 부족 수량과 가장 가까운 충전 상품을 강조한다.

### 충전 상품

| 유료 | 보너스 | 총 지급 | 가격 |
|---:|---:|---:|---:|
| 30 | 3 | 33 | 3,000원 |
| 50 | 6 | 56 | 5,000원 |
| 100 | 12 | 112 | 10,000원 |
| 200 | 24 | 224 | 20,000원 |
| 300 | 36 | 336 | 30,000원 |
| 500 | 60 | 560 | 50,000원 |
| 700 | 84 | 784 | 70,000원 |
| 1,000 | 126 | 1,126 | 100,000원 |

- 상품 카드에는 `유료 + 보너스`, 총 지급량, 원화 가격을 모두 표시한다.
- 충전 완료 시 유료 등껍질과 보너스 등껍질을 별도 원장 항목으로 기록한다.
- 차감 우선순위는 `TBD(P-02A)`다.

### 흐름

1. 서버에서 활성 충전 상품과 가격을 조회한다.
2. 상품 선택 후 토스페이먼츠 결제창을 연다.
3. 성공 URL에서 서버 승인 요청을 보낸다.
4. 승인 완료 후 충전 원장을 기록하고 잔액을 갱신한다.
5. 구매 중이었다면 30분 내 저장된 상태로 복귀한다.

### 상태

`CREATED → PAYMENT_PENDING → PAID → CREDITED`

예외 상태: `FAILED`, `CANCELED`, `REFUNDED`. `PAID` 후 `CREDITED` 실패는 서버 재시도하며 중복 지급하지 않는다.

## 8. 본인용 유료 운세

### 정보·질문

- 본인 또는 저장된 인물을 선택한다.
- 궁합은 상대 인물과 관계를 추가한다.
- 수능은 시험 종류·시험일, 취업은 이벤트 유형·예정일을 받는다.
- 선택형 관심 항목을 제공한다.
- 자유 메모는 결과에 반영되지 않음을 표시한다.

### Checkout

- 상품명, 대상 인물, 옵션, 차감량, 구매 후 잔액을 서버 견적으로 표시한다.
- `사주` / `사주+부적`을 선택한다.
- 잔액 부족 시 충전 모달로 전환한다.
- 구매 확인 시 단일 구매 명령을 한 번만 전송한다.

### 결과

- 로딩 화면 후 `calculationVersion`, `generationVersion`, `contentVersion`과 함께 저장된 결과 스냅샷을 표시한다.
- 신규 결과는 서버 계산 → 구조화 JSON 생성 → Liner 해석 문장 생성 → 응답 검증 → 스냅샷 저장 순서로 처리한다.
- 이미 같은 결과 키의 스냅샷이 있으면 즉시 재사용한다.
- 섹션 간 이동 상태는 URL 또는 결과 내부 상태로 보존한다.
- 사주 구매자는 부적 추가 구매 CTA를 볼 수 있다.
- 결과는 마이페이지에서 계속 재열람할 수 있다.
- 수능 결과는 다음 구조를 반드시 지원한다.
  - 1~5교시별 흐름과 집중 포인트
  - 도시락·간식 추천, 추천 이유, 대안 메뉴
  - 수험표·신분증·도시락/물·아날로그 시계·겉옷 등 공통 준비물
  - 행운 색·아이템·부적 배경화면 등 개인 맞춤 준비물
- 준비물 체크 상태는 기기 로컬에 저장하며 사주 결과 스냅샷을 변경하지 않는다.
- 오행분석 섹션의 사용자 노출은 `TBD(F-09)`다.

### 오류

- 잔액 부족: 충전 안내
- 잘못된 입력: 해당 필드로 이동
- 생성 실패: 차감 복구 상태와 재시도 안내
- Liner 시간 초과·호출 실패·응답 검증 실패: 서버 내부 제한 횟수만 재시도하고 최종 실패 시 구매 실패 및 등껍질 자동 환급
- 중복 요청: 최초 구매 결과로 이동
- 권한 없음: 403 화면

## 9. 부적

### 선택·생성

- 각 운세에 정의된 부적 3종 중 선택한다.
- 동물은 띠 기준이며 경계 기준은 `TBD(T-02)`다.
- 오행·부적 유형으로 의상·소품·배경을 조합한다.
- 이미지에 이름·생년월일·성별을 넣지 않는다.

### 열람·저장·공유

- 원본 1080×1920 PNG, 썸네일 360×640 WebP
- 원본은 권한 확인 후 10분 signed URL로 제공한다.
- iOS는 직접 다운로드가 제한되면 길게 눌러 저장 안내를 제공한다.
- 공유 이미지는 개인정보가 없는 별도 에셋을 사용한다.
- 개인 사주 결과와 부적에는 카카오톡 공유하기를 제공한다.
- 공유 payload에는 생년월일시·성별을 넣지 않는다. 공유할 결과 범위와 카드 구성은 `TBD(G-11)`에 따르며 부적은 개인정보 없는 공유용 이미지를 사용한다.
- 공유 시 서버에서 비식별 공유 리소스를 만든 뒤 Kakao JavaScript SDK의 공유하기를 호출한다.

### 부적 창고

- 구매·선물 부적을 통합 표시한다.
- 동일 동물·종류는 `×N`으로 묶고 상세에서 획득 이력을 표시한다.
- 12지 도감 진행도를 표시하며 완성 보상은 없다.

## 10. 선물 구매

### 위저드 단계

1. 운세 유형 선택
2. `부적` / `부적+사주` 옵션 선택
3. 수신자 이름/닉네임과 알림톡 수신 휴대전화번호 입력
4. 부적 선택
5. 추천 또는 직접 편지 입력
6. 주문 검토·원화 결제

- 위저드 상태는 Zustand + sessionStorage에 보관한다.
- 메시지는 200자, 이모지·줄바꿈 허용, 금칙어 검사, HTML 이스케이프한다.
- `부적` 선물은 부적과 편지를 제공하고, 수능 상품이면 수능 체크리스트를 추가 제공한다.
- `부적+사주` 선물은 부적·편지·사주 결과를 제공하고, 수능 상품이면 수능 체크리스트를 포함한다.

### 결제 완료

- 서버 승인 완료 후에만 선물과 링크를 활성화한다.
- 서비스가 수신자 휴대전화번호로 선물 링크를 포함한 카카오 알림톡을 발송한다.
- 완료 화면에는 알림톡 발송 상태를 표시하고 실패 시 정책에 따른 재시도 또는 CS 안내를 제공한다.
- 수신자 전화번호는 화면·로그·Sentry·PostHog에서 마스킹하며 보관기간은 `TBD(G-10A)`다.
- 알림톡 대행사·발신 프로필·템플릿 심사·SMS 대체 여부는 `TBD(G-10)`다.

## 11. 선물 수신

### 토큰 진입

- 토큰이 없거나 폐기·만료됐으면 선물 정보를 노출하지 않는다.
- 유효한 미사용 링크는 수신자 이름, 보낸 사람 이름, 상품 종류를 표시한다.
- 수신자의 띠가 계산되기 전에는 뿌기 또는 중립 캐릭터를 보여주고, 정보 제출 후 해당 띠 동물로 전환한다.
- 선물 메시지는 OG에 포함하지 않는다.

### 정보 제출

- 수신자가 자신의 생년월일시·성별을 입력한다.
- 한 번 제출하면 잠기고 수정 UI를 제공하지 않는다.
- 오류 시 CS 초기화 안내를 제공한다.

### 결과 공개

- 수신자가 정보를 제출하고 결과 생성이 완료되면 단건 선물 전체를 즉시 공개한다.

### 재열람·계정 연결

- 최초 사용 후 90일까지 링크로 재열람한다.
- 미사용 링크 만료는 `TBD(G-07)`다.
- 로그인 시 부적 창고와 계정에 연결할 수 있다.
- 결과 하단에 `다른 운세도 보러가기` CTA를 제공해 홈 또는 관련 유료 운세로 연결한다.

## 15. 상태 모델

### 본인 구매

`CREATED → DEBITED → GENERATING → FULFILLED`

- 실패: `FAILED → REFUNDED`
- 같은 멱등키의 재요청은 최초 상태와 결과를 반환한다.

### 선물 주문

`CREATED → PAYMENT_PENDING → PAID → ACTIVE → COMPLETED`

- 취소/환불: `CANCELED`, `REFUNDED`

### 알림톡 발송

`PENDING → SENT | FAILED`

- 동일 선물·동일 발송 목적의 중복 발송을 막는 멱등 키를 사용한다.
- 실패 재시도 횟수와 SMS 대체 여부는 `TBD(G-10)`다.

### 선물 수신

`UNCLAIMED → RECIPIENT_SUBMITTED → ACTIVE → COMPLETED → EXPIRED`

- 토큰 재발급 시 기존 링크는 `REVOKED`

### 부적

`PENDING → READY | FAILED`

- 동기/비동기 생성 방식은 `TBD(F-06)`

## 17. 접근성·검증

- 버튼·링크에 접근 가능한 이름을 제공한다.

## 18. 출시 E2E 시나리오

7. 탈퇴 → 접근 차단 → 삭제·법정 보관 분리
