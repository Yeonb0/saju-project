> 최종 정리: 2026-10-02
> 기준: Figma 와이어프레임(node `17:2`), 저장소 문서와 코드, 2026-09-30~10-02 제품 결정
> 용도: PRD·API 명세서·기능 명세서의 단일 결정 원본

## 상태

- `확정`: 후속 문서와 구현에 반영한다.
- `부분 확정`: 방향은 정해졌으나 세부 결정 또는 외부 확인이 남아 있다.
- `미정`: 추가 제품 결정이 필요하다.
- `보류`: 1차 출시 필수 범위에서 제외한다.

## 1. 상품·재화·결제

### P-01. 등껍질 `확정`

- 재화 1종, 표시명 `등껍질`, 내부 코드 `TURTLE_SHELL`

### P-02. 충전 상품 `확정`

- 기준: 유료 등껍질 1개 = 100원
- 모든 충전 상품에 보너스 등껍질을 추가 지급한다.

| 코드(안) | 유료 | 보너스 | 총 지급 | 가격 |
|---|---:|---:|---:|---:|
| `TURTLE_SHELL_30` | 30 | 3 | 33 | 3,000원 |
| `TURTLE_SHELL_50` | 50 | 6 | 56 | 5,000원 |
| `TURTLE_SHELL_100` | 100 | 12 | 112 | 10,000원 |
| `TURTLE_SHELL_200` | 200 | 24 | 224 | 20,000원 |
| `TURTLE_SHELL_300` | 300 | 36 | 336 | 30,000원 |
| `TURTLE_SHELL_500` | 500 | 60 | 560 | 50,000원 |
| `TURTLE_SHELL_700` | 700 | 84 | 784 | 70,000원 |
| `TURTLE_SHELL_1000` | 1,000 | 126 | 1,126 | 100,000원 |

- 유료분과 보너스분은 원장에서 구분 기록한다.

### P-02A. 유료·보너스 차감 우선순위 `미정`

- 사용 시 유료 등껍질과 보너스 등껍질 중 어느 잔액을 먼저 차감할지 결정해야 한다.
- 선택한 순서는 유효기간 소멸, 일부 사용 환불 산식, 지갑 잔액 표시에 함께 적용한다.

### P-03. 본인용 상품 가격 `확정`

| 상품 | 사주 | 사주+부적 | 부적 추가 구매 |
|---|---:|---:|---:|
| 일반 운세 | 30조각 | 45조각 | 15조각 |
| 이벤트 운세 | 40조각 | 55조각 | 15조각 |

- 가격은 서버 상품 카탈로그가 결정하며 클라이언트에 하드코딩하지 않는다.

### P-03A. 선물 가격 `부분 확정`

- 선물은 등껍질이 아닌 원화 직접 결제다.
- 일반·이벤트 단건 선물의 원화 가격은 미정이다.
- 선물 옵션은 `부적` / `부적+사주` 두 가지다. 선물에는 `사주` 단독 옵션이 없다.
- `부적` 선물은 부적과 편지를 제공한다. 수능 상품이면 수능 체크리스트도 제공하되 전체 수능 사주 해석은 제공하지 않는다.
- `부적+사주` 선물은 부적·편지·선택한 운세 결과를 제공하며, 수능 상품이면 수능 체크리스트도 포함한다.
- 단순히 등껍질 수량을 100배해 원화 가격으로 간주하지 않는다.

### P-04. 유효기간·소멸 `부분 확정`

- 유료 재화: 충전일로부터 5년
- 무상 재화: 별도 설정 가능, 기본 180일
- 유효기간이 먼저 끝나는 재화부터 사용
- 소멸 30일 전·7일 전 안내
- 서비스 종료 시 유료 잔액 환불 절차 제공
- 미정: 소멸 안내에 선물용 알림톡 채널을 함께 사용할지 여부. 앱 내 고지는 필수다.

### P-05. 충전 취소·환불 `부분 확정`

- 구매 후 7일 이내이고 전혀 사용하지 않았으면 전액 취소 가능
- 일부 사용 시 미사용 유료 등껍질을 기준으로 환불 검토
- 이벤트·보너스 재화는 현금 환불 제외
- 결과·부적이 생성·공개됐다면 해당 콘텐츠 사용분은 환불 제외
- 시스템 장애로 생성되지 않으면 즉시 자동 복구
- 미성년자는 관련 법령·PG 정책에 따른 법정대리인 취소 절차 제공
- 결제 전에 디지털 콘텐츠 제공 개시 후 청약철회 제한 가능성을 고지
- 미정/외부 확인: 일부 사용 환불 산식·수수료·반올림, PG 부분 취소 실패 처리, 등껍질 법적 분류와 약관 검토

### P-06. 잔액 부족 `확정`

- 충전 안내 모달에 부족 수량과 가장 가까운 충전 상품 표시
- 충전 후 선택한 운세·인물·옵션을 복원
- 구매 상태 최소 30분 유지

### P-07. 선물 결제 `확정`

- 1차 출시는 원화 직접 결제
- 등껍질은 본인용 운세·부적 구매에 사용
- 등껍질 선물 결제는 출시 후 검토

### P-08. PG `부분 확정`

- 토스페이먼츠 기준 구현
- 신용·체크카드 필수
- 계약상 가능한 카카오페이·토스페이·네이버페이 등 간편결제 노출
- 휴대폰 소액결제 제외
- 외부 확인: 운세·부적·충전형 재화 가맹점 승인, 실제 간편결제 목록, 부분 취소와 미성년자 처리 조건

### P-09. 구매 원자성·멱등성 `확정`

- 등껍질 차감과 콘텐츠 구매는 하나의 서버 구매 명령으로 처리한다.
- 공개된 독립 `등껍질 차감 API`는 만들지 않는다.
- 서버가 잔액 확인 → 원장 차감 → 구매 생성 → 결과 생성을 조정한다.
- 일시 오류는 재시도하고 최종 실패 시 보상 거래로 즉시 환급한다.
- DB·PG·R2는 하나의 ACID 트랜잭션으로 간주하지 않고 상태 머신·재시도·보상 처리로 맞춘다.

## 2. 운세 상품과 결과

### F-01. 입력 정보 `확정`

- 공통: 이름/닉네임, 생년월일, 양력/음력, 윤달, 태어난 시·분 또는 시간 모름, 성별
- 궁합: 상대방 공통 정보 + 관계
- 수능운: 시험 종류, 시험일
- 신살: 선택형 관심 항목을 받되 세부 항목은 `TBD(F-03)`
- 상세 질문은 선택형 관심 항목으로 제공한다.
- 자유 메모는 결과에 반영하지 않고 화면에만 표시한다.

### F-02. 결과 구성 `확정`

| 운세 | 결과 순서 |
|---|---|
| 애정운 | 한줄 요약 → 현재 흐름 → 좋은 시기 → 주의점 → 행동 팁 → 부적 |
| 종합운 | 한줄 요약 → 전체 흐름 → 인간관계 → 학업·일 → 재물 → 컨디션 → 행운 포인트 → 부적 |
| 재물운 | 한줄 요약 → 재물 흐름 → 들어오는 운 → 지출 주의 → 좋은 시기 → 행동 팁 → 부적 |
| 궁합 | 요약 → 잘 맞는 부분 → 부딪히는 부분 → 대화 방식 → 관계 팁 → 부적 |
| 신살 | `TBD(F-03)` |
| 수능운 | 한줄 요약 → 시험 당일 → 교시별 → 집중 포인트 → 도시락·간식 → 준비물 → 긴장 관리 → 부적 |

### F-03. 신살 결과 구성 `미정`

- 다룰 신살의 범위, 노출 방식, 해석 섹션, 부적 연결 기준을 확정해야 한다.

### F-04. 질문 반영 `확정`

- 선택형 질문 유형을 Liner 생성 맥락 키로 사용
- 자유 메모는 AI·규칙 엔진으로 해석하지 않음

### F-05. 재열람 `확정`

- 계정 유지 중 무제한 재열람
- 구매 당시 결과와 `calculationVersion`, `generationVersion`, `contentVersion`을 스냅샷 저장
- 탈퇴 시 개인 결과 삭제, 법정 거래정보만 분리 보관

### F-06. 생성 방식 `부분 확정`

- 만세력 계산과 Liner 해석 문장은 구매 직후 동기 생성
- 정상 요청에서 텍스트 결과 스냅샷까지 완료
- Liner 시간 초과·호출 실패·응답 검증 실패는 서버에서 제한 재시도하고 최종 실패 시 오류 상태와 재화 복구
- 미정: Liner 호출 제한시간과 최대 재시도 횟수
- 미정: 부적 이미지 합성·R2 업로드를 동기 응답에 포함할지 별도 작업 상태(`PENDING/READY/FAILED`)로 처리할지

### F-07. 이벤트 판매 종료 `부분 확정`

- 단건 수능운: 수능 전날 23:59까지 판매
- 구매 결과는 시험 후에도 재열람 가능
- 시험 후 홈 신규 구매 비활성화, 보관함에서 접근

### F-08. 고지 `확정`

- 결제 버튼 위와 결과 하단에 재미·참고용 콘텐츠 고지
- 공유 이미지 하단에 `재미로 보는 운세 콘텐츠` 표시

### F-09. 오행분석 노출 `미정`

- 초기 와이어프레임에는 본인 구매 흐름의 `오행분석?` 메모가 있다.
- 사주 계산 내부에서는 오행 분포를 사용하지만, 이를 별도 유료 결과 섹션·차트·설명으로 사용자에게 노출할지는 확정되지 않았다.
- 노출한다면 모든 운세 공통 섹션인지 종합운 전용인지, 무료 미리보기를 제공할지도 결정해야 한다.

## 3. 선물하기

### G-05. 수신자 정보 `확정`

- 구매자는 이름/닉네임과 알림톡 발송용 휴대전화번호를 입력
- 수신자가 생년월일시·성별 직접 입력
- 최초 제출 후 잠금
- CS가 입력 상태 초기화 가능
- 공개 후 초기화·재생성은 영향 확인 및 감사 로그 기록

### G-06. 수신자 로그인 `확정`

- 링크 열기·정보 입력·결과 열람은 비로그인 가능
- 부적 창고·계정 재열람·다기기 복원은 로그인 필요

### G-07. 링크 만료 `부분 확정`

- 최초 사용 후 90일간 링크로 재열람 가능
- 구매자가 링크 재발급을 요청하면 기존 링크를 폐기하고 새 링크를 알림톡으로 재발송
- 미정: 정보 입력 마감과 미사용 링크 만료기간

### G-08. 메시지 `확정`

- 최대 200자, 이모지·줄바꿈 허용
- 추천 5개, 최소 금칙어 필터
- OG·검색 결과에 미노출
- HTML 이스케이프 적용

### G-09. 선물 환불 `부분 확정`

- 미개봉·미제공이면 구매 후 7일 이내 전액 취소
- 최초 결과 또는 부적 공개 후 제공분 환불 제외
- 시스템 오류로 콘텐츠가 제공되지 않으면 전액 환불
- 미정: `개봉` 기준과 공개/실열람 중 제공 개시 기준

### G-10. 알림톡 `부분 확정`

- 선물은 수신자 휴대전화번호로 카카오 알림톡을 발송해 전달한다.
- 알림톡에는 추측 불가능한 선물 링크를 포함한다.
- 일반 결과·부적 공유는 선물 전달과 분리하며 카카오톡 공유하기를 사용한다.
- 미정: 알림톡 발송 대행사, 발신 프로필·템플릿 심사, 발송 실패 시 재시도·SMS 대체 여부.

### G-10A. 알림톡 수신 전화번호 보관 `미정`

- 결제·발송·재발송·분쟁 대응에 필요한 최소 보관기간과 삭제 시점을 정해야 한다.
- 저장 중에는 암호화하고 화면·로그·Sentry·PostHog에서는 마스킹한다.

### G-11. 개인 output 카카오톡 공유 `부분 확정`

- 개인 사주 결과와 부적에 카카오톡 공유하기를 제공한다.
- 공유 리소스에는 생년월일시·성별 등 인적정보를 포함하지 않는다.
- 미정: 사주 결과 전체/선택 섹션/요약 카드 중 공유 범위, 공유 링크 만료기간, 사용자의 공유 철회 기능.

## 5. 사주 계산·콘텐츠

### S-01. 계산 기준 `부분 확정`

- 한국 출생, `Asia/Seoul`
- 연주·월주는 입춘·절기 전환 시각 기준
- 1차 제외: 진태양시 보정, 해외 출생 시간대 보정
- 미정: 자시 일주 경계 23:00/00:00, 조자시·야자시 분리 여부

### S-02. 검증 `부분 확정`

- 최소 50개 기준 케이스
- 공신력 있는 역법 데이터와 서로 다른 만세력 2개 이상 비교
- 사주 원국 네 기둥이 모두 일치해야 출시
- 불일치 사례를 회귀 테스트로 유지
- 미정: 충돌 시 단일 최종 기준, 라이브러리와 버전

### S-03. 결과 재사용 키 `확정`

- `정규화된 인물정보 + 상품 코드 + 기준일/이벤트일 + calculationVersion + generationVersion`
- 사용자 계정은 시드에서 제외
- 같은 키에 성공 결과가 있으면 Liner를 다시 호출하지 않고 최초 스냅샷 재사용

### S-04. 결과 스냅샷 `확정`

- 구매 결과 전체와 `calculationVersion`, `generationVersion`, `contentVersion` 저장
- 콘텐츠 업데이트가 과거 결과를 바꾸지 않음

### S-05. 생성 설정·콘텐츠 관리 `확정`

- Liner 프롬프트, 입력·출력 스키마, 금지 표현, 추천 데이터 카탈로그를 Git에서 버전 관리
- `draft → review → approved → deployed`
- 변경 시 `generationVersion` 또는 `contentVersion` 증가 및 직전 버전 롤백

### S-06. 생성형 AI·Liner 역할 `확정`

- 사주 원국, 간지, 십성, 12운성, 합충형파해, 대운·세운은 오픈소스 만세력 라이브러리와 서버 계산 엔진이 담당한다.
- Liner API는 계산 엔진이 반환한 구조화 JSON을 입력받아 사용자용 사주 해석·설명 문장만 생성한다.
- Liner는 계산 결과에 없는 명리 정보를 임의로 계산·보완·추론하지 않으며, 값이 없으면 해당 내용을 생성하지 않는다.
- 자유 메모와 원본 생년월일시 등 불필요한 개인정보는 Liner 입력에서 제외한다.
- AI 상담 채팅과 자유 질문 해석은 제공하지 않는다.

- 외부 ID UUID, 숫자 PK 비노출
- 토큰: 안전한 난수 32바이트 이상 Base64URL
- gift 영구 저장값은 토큰 해시만 유지한다. 알림톡 발송에 필요한 원문 URL은 암호화된 outbox에 한시 저장하고 발송 성공 또는 재시도 기간 종료 후 삭제한다.
- 로그·Sentry·분석에 원문 금지
- 재발급 시 기존 토큰 폐기
