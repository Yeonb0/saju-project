# 퀵오픈·출시 준비 공통 요청서

기준일: 2026-10-15
목적: 토스페이먼츠 퀵오픈 결정 뒤, 심사용 사이트와 실제 사용자 흐름을 안전하게 준비한다. 이 문서는 업무 요청을 한곳에 모은 것이며, 비밀값·원본 개인정보·PG 키를 기록하지 않는다.

## 공통 원칙

- 사용자 화면의 가상 재화 명칭은 **등껍질**이다.
- 실제 결제 완료는 충전 주문이 `CREDITED`이고 지급 원장·잔액이 함께 확정된 경우만 표시한다. 결제/지급 결과가 불명이면 새 결제를 만들지 않고 기존 주문을 조회·대사한다.
- 운영 환경 변경, 라이브 키 설정, 실제 결제, 판매 활성화는 이 문서의 요청만으로 수행하지 않는다. 담당자가 별도 승인된 절차에서 시행한다.
- 퀵오픈 1차 선물은 구매자 직접 링크 전달로 먼저 출시한다. 카카오 알림톡은 폐기한 요구사항이 아니라 후속 2차 전환이며, 실제 대행사·템플릿·서명 webhook·전화번호 보관 정책이 확정된 별도 feature에서 진행한다. BE-B의 현재 구현 범위에는 알림톡 adapter가 없다.

## 출시 전 공동 확인

1. 두 개의 별도 브라우저 계정으로 카카오 로그인, 세션, CSRF, 타인 리소스 404를 확인한다.
2. 소액 승인 1건은 별도 승인된 안전한 설정에서만 수행하고, 주문 `CREDITED`·지급 원장·잔액·등껍질 사용 결과를 같은 식별자로 대사한다.
3. 중복 confirm/webhook, provider timeout, 브라우저 새로고침에서는 추가 지급·추가 구매가 없고 기존 주문/구매 조회로 수렴하는지 확인한다.
4. 부적/선물은 개인정보·raw token·signed URL이 API 응답 외 로그·analytics에 남지 않는지 점검한다.
5. staging PostgreSQL migration, worker 중단/재시작, DB·파일 복원 및 PG 대사 절차는 운영 배포 전에 별도 연습한다.

## BE-B가 임의로 결정하지 않는 항목

- 토스 퀵오픈/정산/결제수단/충전 한도와 실제 판매 활성화
- 라이브 키와 웹훅의 설정·실결제
- 심사용 사업자·정책·고객센터·상품 원고
- 부적의 최종 이미지, 문구, 저작권 및 content version
- 부적의 실제 이미지/문구 최종본과 일반 운세·부적의 공개 공유 범위
