# 운세 응답 품질 평가 기준

## 목적

Liner 응답과 결정론적 fallback이 같은 최소 품질 계약을 지키도록 한다. 평가는 운세 내용의 적중 여부가 아니라 서버가 보장할 수 있는 구조, 근거성, 안전성, 구체성을 대상으로 한다.

## 배포 차단 기준

다음 항목은 하나라도 실패하면 해당 응답을 저장하거나 제공하지 않는다.

- JSON Schema와 요청된 섹션 목록을 정확히 준수한다.
- `sourceFactKeys`는 서버가 전달한 scalar fact 경로만 참조한다.
- 좋은 시기, 부족 오행, 궁합 섹션은 각각 `luck`, `fiveElements`, `counterpart` 근거를 포함한다.
- 결과·합격·수익·질병·죽음을 확정하거나 시스템 프롬프트를 노출하는 표현이 없다.
- 섹션 간 토큰 유사도가 0.90을 넘는 복제성 문장이 없다.
- 수능 응답은 별도의 구조화 가이드를 빠짐없이 포함한다.

## 자동 회귀 평가

`ReadingQualityRegressionTest`는 서로 다른 생년월일시 5개와 운세 유형 6개를 조합한 30개 golden scenario를 실행한다. 각 시나리오는 실제 만세력 계산 → 안전 fact projection → fallback 생성 → 운영 validator 검증의 전체 경로를 거친다.

이 테스트는 최소한 다음 회귀를 탐지한다.

- 계산 결과 구조가 바뀌어 근거 경로가 깨지는 문제
- 새 섹션이 fallback에서 누락되는 문제
- 여러 섹션에 같은 문구를 재사용하는 문제
- 수능 구조화 응답의 필수 필드가 사라지는 문제
- 안전 표현 정책을 위반하는 문구가 추가되는 문제

## Liner 샘플 평가 운영

외부 모델 출력은 배포 후보마다 운세 유형별 최소 5건, 총 30건 이상을 수집해 validator 통과율을 확인한다. 목표는 1차 응답 통과율 95% 이상, 최대 3회 교정 후 통과율 99% 이상이다. 실패 코드별 비율을 집계하고 `LINER_SCHEMA_INVALID`, `LINER_SOURCE_FACT_INVALID`, `LINER_SECTION_EVIDENCE_MISMATCH`, `LINER_SECTION_TOO_SIMILAR`, `LINER_FORBIDDEN_EXPRESSION` 중 어느 하나라도 1%를 넘으면 프롬프트 또는 스키마를 재검토한다.

정성 검수에서는 섹션별로 다음 0~2점 척도를 사용한다.

| 항목 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 근거 연결 | 입력 사실과 무관 | 사실 언급은 있으나 연결이 약함 | 인용한 사실이 해석과 명확히 연결됨 |
| 구체성 | 추상적 문구뿐 | 일부 행동 제안 | 바로 실행 가능한 조건·순서가 있음 |
| 섹션 차별성 | 다른 섹션과 동일 | 관점만 조금 다름 | 목적과 정보가 분명히 다름 |
| 안전성 | 확정·공포·권유 | 면책은 있으나 오해 가능 | 한계를 밝히고 현실 판단 기준을 제시 |
| 한국어 자연스러움 | 부자연스럽거나 번역투 | 이해 가능 | 간결하고 자연스러움 |

평균 8점 미만 또는 한 항목이라도 0점인 샘플은 실패로 처리한다. 사람 평가 결과는 프롬프트/콘텐츠 버전과 함께 기록해 이전 버전과 비교한다.
